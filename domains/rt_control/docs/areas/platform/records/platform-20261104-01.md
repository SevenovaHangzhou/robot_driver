## 背景

上传前隔离构建通过，但全量测试暴露两个独立问题：`control_api_adapter` 的信号退出
存在 ROS context 提前关闭的竞态；Runtime-LOG 压力测试未达到有效样本数。
历史记录将后者列为既有失败，本次保留采样量断言并继续定位读者行为。

## 改动

- `vacuum_adapter` 与 `module_state_adapter` 使用与 position adapter 相同的受控信号退出：
  请求停止、等待执行器回调结束、销毁 action server/节点、最后关闭 context，并恢复原信号处理器。
  真空 action waitable 在节点销毁前显式释放。
- 现有跨进程回归测试扩展到三个适配器，检查 SIGINT/SIGTERM 下真实 ROS 对象的释放顺序；
  修复前两种信号均能稳定复现失败，修复后通过。测试只创建隔离 DDS 图，不创建硬件节点。
- SHM 读者从快照的最新槽位开始复制，再反转为时间顺序返回，防止快速写入反复覆盖最旧槽位
  导致读者饥饿；序号二次确认、防撕裂、读游标、丢帧统计及共享内存格式保持原语义。
- 基准工具增加显式 `--stream` 测试模式：发布 ready 后等待 stdin 启动，持续写入且不积累
  统计向量。压力测试不再依赖固定三百万周期的机器运行时长，仍要求有效样本 >1000，
  额外验证覆盖发生，并逐项检查全部 64 个字段。测试结束关闭读者及管道并回收自己的写者。
- 使用固定 ruff 0.11.13 / clang-format 14 修正新增 Python 文件与 C++ 改动行的格式，
  清理六处未使用导入；移除新增记录插件 CMake 中不符合仓库约定的 `-Werror`。
- 临时 launcher 备份不纳入提交；未覆盖现有生产 build/install，所有验证使用独立临时目录。
