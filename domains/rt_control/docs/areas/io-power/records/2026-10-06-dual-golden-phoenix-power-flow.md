# 双金凤凰电池充放电流程方案

本文件记录电气与控制流程，不是完整的实车操作规程。用户报告两块电池人工并联
放电已实测可行，且 `0x01`/`0x02` 的 `0x90` CAN 查询均有回复；这仅证明所述
人工连接与查询场景，不证明自动合闸、自动故障隔离或充电路径已验收。用户已授权
`bms_node` 增加 D9 与 K2 软件控制；当前用户确认的 CAN 卡接口为 SocketCAN `can0`，
不再依赖先前 USB-CAN 适配器的序列号。代码通过该接口查询，
提供可配置的话题和 CAN 写路径，但安装配置
仍默认禁用自动控制，K2 实体驱动和安全链未接入。以下动作是准入后的目标行为，
不能凭软件测试认定继电器、MOS 或整机供电已经完成实机验证。

## 拟议接线与前提

- `0x01` 为带实体开关 S1 的主电池：人工打开 S1 后，主电池先经原有放电路径
  给工控机和主控供电。主控启动程序前不能依赖 CAN 指令维持自己的启动电源。
- `0x02` 为副电池，其**放电输出支路**增设常开直流继电器，暂称 K2。
  K2 默认断开；工控机启动、程序重启、控制电源丢失或控制信号失效时均保持断开。
  K2 是新增器件，不是图纸已有的 KM1；本方案不控制或推断 KM1 的状态。
- 两块 BMS 共用 250 kbit/s CAN，地址分别为 `0x01`、`0x02`，主机地址为 `0x40`。
  用户报告已在现场验证：K2 断开时 `0x02` 的 BMS 仍能独立上电并应答 CAN 查询，
  因此可在合闸前读取副电池状态。尚未归档原始回复帧和辅助触点记录；这一项验证
  不代表 K2 的放电支路隔离、失电行为或合闸安全性已完成验收。
- K2 的实际安装位置、接点数量、额定直流开断能力、熔断保护、线圈供电、
  常开/失电状态、辅助触点回读以及是否存在绕过 K2 的充放电路径，必须由电气图
  和实物确认。只有证实 K2 断开能隔离 `0x02` 的放电路径，才可称为“物理断开”。
  原图中的 D1/D2 防止反灌，但不提供均流或限流；K2 合闸浪涌和预充需求也须验证。

依据：《1-七曜星三代机器人.pdf》图纸 03、04、05；《电池-金凤凰.pdf》V1.1。
现有图纸未画出 K2，因此以下步骤以完成上述硬件改造和回读验收为前提。
软件约定 `/bms/k2/command` 的 Bool `true` 为闭合请求、`false` 为断开请求，
`/bms/k2/closed` 为真实辅助触点；`/bms/loads/stop_request` 与
`/bms/loads/stopped` 分别是停负载请求和反馈。发布话题本身不构成实体继电器动作。

## 设计依据与验证口径

- 金凤凰 V1.1 协议明确 `0x90` 提供总压/电流/SOC、`0x93` 提供 MOS 状态、`0x98`
  提供故障位；其默认应答/定制广播周期写为 200 ms。协议没有给出两块电池合闸
  压差、继电器开断电流或稳定时间，因此 200 ms 仅是检查周期，不是安全阈值。
- [Orion 的并联电池设计说明](https://www.orionbms.com/manuals/pdf/parallel_strings.pdf)
  指出不同电压的电池支路接入可能产生损伤性浪涌，且二极管/接触器方案仍需考虑
  接触器粘连等单点故障；该资料不是本机金凤凰电池的许可压差规格。
- [TI 的双电池供电说明](https://www.ti.com/document-viewer/lit/html/SSZT272/GUID-62939FE-18F2-4234-B7F4-2B0C3AF7590B)
  指出支路电压和阻抗差会改变分担电流。[TE 的接触器说明](https://www.te.com/en/faqs/high-voltage-automotive-contactors-and-relays.html)
  指出合闸浪涌可能需要预充；其示例预充百分比不是 K2 的验收值。
- 用户已报告 K2 断开时 `0x02` BMS 可独立上电并应答、两块电池人工并联放电可行，
  并提供了两个地址的 `0x90` 回复，此项记为**现场口述及帧记录**。
  无原始记录时可用上述资料说明设计理由，但不能将资料标成该车继电器、MOS、
  电压阈值或故障关断的**实测成功**。整套流程的 `verified` 仍为 `UNVERIFIED`。

## 启动与副电池接入

1. **初始状态**：两路充电器断开，大功率负载停止；K2 辅助触点确认断开。
   若无可信的断开回读，禁止自动接入副电池。人工打开 `0x01` 的 S1，让主电池
   给工控机和主控供电，然后启动监控程序。程序启动不自动合 K2。
2. **每 200 ms 检查两块电池**：分别查询 `0x90`（总压、电流、SOC）、`0x93`
   （充放电/MOS）和 `0x98`（故障），按 CAN 源地址分别归属，检查报文新鲜度。
   单体电压 `0x91/0x95`、温度 `0x92`、充电器接入 `0x94` 也须在接入前完成检查；
   `0x95` 为多帧数据，扫描调度和总线负载须另行验证，不能把收到一帧当作全组有效。
   任一地址失联、状态过期、故障位有效或关键数据不可解释时，K2 保持断开。
3. **低负载并入判定**：负载保持停止，确认两块电池均无故障、未充电，
   `0x01` 已稳定供电；比较两块电池在 K2 两侧的实际电压与 `0x90` 总压。
   只有 `|V01 - V02| <= ΔV_join`，且两块电池的电流、单体电压和温度均在
   许可范围内，连续满足 `T_stable` 后才允许合 K2。`ΔV_join`、电流/温度限值、
   `T_stable`、通信超时及合闸浪涌/预充要求均为 **TBD**：须由电池厂家和电气负责人
   依据电池、二极管、继电器及母线参数与验证给出，不以其他型号的公开数值放行。二极管不能替代
   这些条件，也不能保证两块电池平均分担电流。
4. **接入 `0x02`**：先核实副电池放电 MOS 的开/关编码及实际状态；如确需
   `D9=1`，使用本次已授权的软件写入口，但仍须完成参数与实体硬件准入。
   确认合闸条件仍成立后才驱动 K2，
   读取辅助触点确认闭合；随即继续查询 `0x02` 的 `0x90/0x93/0x98`，观察其电流、
   母线电压和负载状态。CAN 写应答或线圈命令成功都不等于 K2 已闭合或 MOS 已导通。
5. **运行中检查**：保持两地址每 200 ms 的核心状态检查。若电池电压差超过
   `ΔV_trip`，立即禁止继续接入并停止大功率负载；在确认支路电流已降至允许开断范围后，
   关闭 `0x02` 放电 MOS（仅在参数已验收且通信仍可用时），再断开 K2 并验证辅助触点。
   `ΔV_trip` 及其防抖/滞回仍为 **TBD**，须与 `ΔV_join` 分别验证；若无法确认可安全
   开断，交由独立硬件保护与现场处置，不以软件命令强行切断高电流。

## 故障与关机

- 任一电池 `0x98` 报有效故障、状态过期或 MOS 状态异常，立即禁止 K2 新合闸并
  要求整机安全/控制链停止大功率负载。启用前须验收参数与硬件；启用后对
  **发生故障的那块电池**执行 `D9=0` 关闭其放电 MOS，并以 `0x93` 与实际
  电压/电流确认。当前代码在超时前重发 D9 并检查后续 `0x93`，但超时后
  不能声称 MOS 已关闭或支路已隔离。默认禁用时依赖独立保护。
  软件轮询不代替急停、短路、热失控等独立硬件保护。
- `0x02` 故障时，在支路电流降至继电器允许开断范围后断开 K2 并验证辅助触点，
  锁存故障，不自动重合。若 CAN 失联或 MOS 无法关断，仍需由额定的独立保护路径
  处理，不能把 K2 命令成功当作已隔离。
- `0x01` 的 S1 是人工开关，程序不能操作 S1；`0x01` 故障时通过 D9 请求关闭
  其放电 MOS。它可能是工控机当前电源，发出命令后
  工控机可能立即失电，因此先停止负载、安排受控关机及独立故障保护。
  不因主电池故障自动合 K2 或未经验证地转移负载。若两块都故障，分别执行对应
  故障隔离；即使第二块故障发生在第一块已锁存后，也须再次停负载并处理第二块。
  K2 保持断开；恢复须人工排除原因后重新走启动流程。
- 正常关机目标流程是先停止大功率负载，低电流下退出 `0x02` 放电并断开 K2，
  确认辅助触点后关闭程序和工控机，最后按已批准的方式关闭 `0x01` 的 S1。
  当前节点尚未实现受控关机序列，不可直接将停止程序当成上述流程。

## 充电

充电与机器人运行互斥，原图明确注明“充电时，不得连接设备工作”。充电前停止负载、
关机并确认 K2 断开；K2 断开只能证明经验证的副电池放电支路隔离，不能推定充电器
不会通过其他路径给母线供电。G1/G2 分别连接对应电池的充电口，插口身份、K2 两侧
的充电电流路径、与主电池 S1 的关系及能否机上充电均须由电气负责人确认。
本阶段不发送 `DA`，充电 MOS 由 BMS 管理；未完成电源路径和互锁验证前不执行机上充电。

## 实施前必须闭合

| 项目 | 必须取得的证据 | 未闭合时的行为 |
| --- | --- | --- |
| K2 硬件 | 新图纸、直流额定开断/浪涌、默认断开、辅助触点、无旁路和失电测试 | K2 不接入控制系统，不执行双电池合闸 |
| 副电池只读状态 | K2 断开时可应答已由用户现场确认；仍需归档 `0x02` 的 `0x90/0x93/0x98` 原始帧、响应时序及 K2 断开回读 | 证据归档和关键字段核对前不自动合 K2 |
| 并入和退出参数 | `ΔV_join`、`ΔV_trip`、`T_stable`、电流/温度/单体限值、预充及开断条件的厂家/电气签核 | 不自动合 K2，也不宣称运行中可安全开断 |
| 写控制 | D9 与 `0x93` MOS 原始值的实测映射、负载停止反馈、故障时工控机供电保持或独立保护 | 已授权代码入口；证据未齐时保持默认禁用，BQ-152 的现场准入限制仍有效 |
| 充电路径 | 两充电口身份、K2/S1/二极管的实际路径和“设备不得工作”互锁 | 不执行机上充电 |

判定接入验证成功至少需要：记录同一次 K2 合闸前后两块电池的 `0x90/0x93/0x98`、
K2 辅助触点、母线和 K2 两侧电压及支路电流；确认合闸和退出时电流未超过所选 K2
与 BMS 的额定条件，故障/通信中断时完成预期隔离。缺少器件型号、额定值或这些
现场结果时，只能完成设计审查，不能填写“验证成功”。

验收顺序：静态接线和 K2 常开/回读检查、K2 断开时双 BMS 只读通信、主电池
独立供电、经批准的低负载副电池接入、故障与失电退出、充电路径验证，最后才是
整机工作。本文和离线测试均不等于实机安全验收。
