# EtherCAT PP Grippers

ELECTRI-118 adds an opt-in `robot_hw_ethercat/ZeroErrPpSlave` module to the
existing EtherCAT driver. The existing CSP families and production profiles do
not select this module. No second master, controller loop or bus watchdog is created.

## Controller

Use the pinned `position_controllers/GripperActionController` with `pp.enabled:
true`, one instance per gripper. Its narrow upstream patch is
`patches/ros2_controllers/0003-opt-in-pp-gripper-commands.patch`.

`~/gripper_cmd` is the standard `control_msgs/action/GripperCommand` Action.
Position is the calibrated gripper opening in metres; max_effort is a strictly
positive force limit in newtons. Non-finite, out-of-range and zero/unlimited
force requests are rejected. A busy gripper rejects another goal; cancel and
wait for the result before submitting a replacement. There is no motion queue.

The controller's `max_effort` parameter is an operational admission ceiling;
the hardware profile's `max_force` and `max_torque_permille` are independent
hard software ceilings. The operational ceiling must not exceed the hardware
ceiling. Neither substitutes for the drive's protective settings or hardware safety.

Command interfaces: `position`, `max_effort`, `pp_sequence`, `pp_halt`.
State interfaces: `position`, `velocity`, `effort`, `pp_sequence`, `pp_state`.
The module additionally exports `status_word` and accepts `control_word`, owned
only by `enable_manager`. The controller never claims `control_word`.

Position, force and sequence come from one fixed-size realtime command buffer.
The non-RT Action timer publishes feedback/results; PP update does not invoke
Action methods or their blocking mutexes. Sequence identities survive controller
reactivation by continuing above the hardware's last sequence.

## Hardware Contract

The module reuses GenericEcSlave for PDO/SDO configuration and registration.
It owns the following raw channels and rejects duplicates, missing channels,
generic interface mappings and secondary factor/offset conversions:

| Direction | Objects and raw types |
| --- | --- |
| RxPDO | `6040:uint16`, `6072:int16`, `607A:int32` (8 bytes) |
| TxPDO | `6041:uint16`, `6061:int8`, `6064:int32`, `606C:int32`, `6077:int16`, trailing `0000:00:uint8` pad (14 bytes) |

One RxPDO and one TxPDO are accepted. The final dummy byte is required for the
ESC's even-byte alignment and never becomes a ROS interface or runtime data
channel. Missing, misplaced, duplicate or differently sized padding is rejected.
CoE readbacks from all sixteen Gen3 drives and the supplied ESI agree on signed
`6072`; positive torque-limit counts must fit `int16` (at most 32767). This type
bound is not an approved physical force limit; per-gripper calibration remains required.

PDO assignment indices are not prescribed. They must come from the actual ESI
and firmware. Explicit SDOs are required for mode `6060:int8=1`, profile velocity
`6081:uint32`, acceleration/deceleration `6083/6084:uint32` and halt option
`605D:int16`. Profile values must be approved commissioning values; motion ramps
are generated by the drive, not by the controller. SDO writes to control word,
target position or max torque are rejected to preserve output ownership.

The local ZeroErr manual's section 8.2.84 defines `6072` in rated-current
permille. This implementation uses that object, not `6073` or `60E0/60E1`.
The supplied manual and older ESI have inconsistent type/access descriptions;
the real firmware and PP-mode limit behavior must be verified before use.

Calibration is explicit and currently supports an affine opening-to-counts
mapping. `permille_per_newton` must be a verified conservative conversion over
the entire permitted stroke, not a guessed motor constant. A nonlinear linkage
without a valid conservative mapping is unsupported. `effort_newtons_per_unit`
provides an estimated force from motor feedback, not a force-sensor measurement.

The adapter sends the target and downward-rounded force limit with new-setpoint
low and Halt high first. Only after a sent packet and cleared acknowledgment
does it raise bit 4, wait for bit 12, lower bit 4, then wait for bit 12 to clear.
Absolute PP targets are used; bits 5/6 remain clear. Success requires this
handshake, matching sequence, target-reached status and positional tolerance.

Cancellation retains the last force limit and asserts Halt. `CANCELED` is only
reported after the configured number of sent cycles with sufficiently low
velocity and cleared acknowledgment. Missing acknowledgment, stop timeout,
invalid feedback, mode mismatch and drive faults fail closed. Operation timeout
aborts the Action and requests Halt; it does not claim the drive has stopped.
Stalling also requests Halt before completion; `allow_stalling` only changes the
terminal Action status and must not be interpreted as proof of a successful grasp.

Disable, quick-stop and fault-reset control words take precedence over PP bits.
Loss of enable or valid process data invalidates the old sequence: no automatic
motion replay. Startup requires an exact raw-position preload that was actually
sent. The cycle hooks in `patches/ecat_icube/0013-coherent-pdo-cycle-hooks.patch`
propagate the master's existing WC result before update and at output preparation.
Rebuild all EtherCAT packages together because the EcSlave virtual interface changes.

## Integration Status

`rt_control_start --enable-only` now provides a separate stationary enable test.
The owner template `config/machines/zeroerr_stationary.yaml` exports only a
control-word command, preloads actual raw position and holds it after enable.
It uses 14 CSP + 2 PP modes, without starting PP trajectories or writing 60FE
(brake/digital output) or force objects. User-confirmed zeros are stored in
`config/machines/alfa_v3_mechanical_zero.yaml` as raw output-encoder counts.
This entry has passed one real enable/hold/disable/shutdown cycle; it does not
make the following PP motion/calibration prerequisites complete.

`config/grippers/zeroerr_pp.draft.yaml` and bringup's
`config/alfa_v3_grippers.draft.yaml` are installed templates, not launchable
production configurations. `verified: false` and TBD fields deliberately block
setup. The existing alfa_v3 physical-profile/control-scope static gate stays closed.

The arms-only physical inventory is recorded in
[`config/machines/alfa_v3_arms_only.draft.yaml`](config/machines/alfa_v3_arms_only.draft.yaml):
left X2 positions 1..7 are J1..J7 in CSP and position 8 is the PP gripper; right
X3 positions 9..15 are J1..J7 in CSP and position 16 is the PP gripper. Coupler
positions 0/17 are non-motion responders. Identities and positions came from the
read-only scan, and joint order came from the user's confirmation. This file is
an installed commissioning inventory, not a registered runtime variant.

Current maps and selected SDO values are preserved in
[`alfa_v3_protocol_readback.yaml`](config/machines/alfa_v3_protocol_readback.yaml).
Both grippers currently report mode 8. The CSP draft preserves the directly
read 10-byte maps; the PP draft proposes an 8-byte RxPDO and 14-byte TxPDO remap.
No remap or mode change has been sent to the drives.

All sixteen drives return object-not-found for `605D`, including both grippers
(software strings `550403170` / `550729090`). The adapter's required Halt-policy
configuration is deliberately retained pending vendor confirmation; removing it
would not establish safe cancellation. Error register `603F` also reads `730F`
at positions 3/8/12/16 (manual: multi-turn encoder holding battery low).
These reads require field follow-up and do not alone establish the current
CiA402 Fault state.

User-approved encoder usage is recorded in the arm inventory: only left J3
(position 3) and right J4 (12) may use the single-turn startup battery-fault
reset policy, subject to a verified output range that never crosses the encoder
wrap boundary. The grippers (8/16) require valid battery-backed multi-turn
references. After the user fitted batteries, both grippers reported `7314`
(battery reconnection), while 3/12 still reported `730F`. An encoder reset via
`2242` may affect the turn reference and is not part of automatic startup.
These are commissioning requirements; runtime wiring is still incomplete and
the inventory remains draft. The original readback snapshot is historical.

Real joint names/model, remap and Halt-policy qualification, calibrated coefficients, profile
timing/limits and scope-specific controller lifecycle composition remain
integration prerequisites. This change does not publish a new cross-domain `/rt`
endpoint or change the frozen robot_interfaces contract. It also does not add
grippers to the legacy JTC or enable_manager's old-machine joint list.

## Offline Tests

After importing frozen dependencies and applying patches in bootstrap order:

```bash
colcon build --packages-up-to gripper_controllers robot_hw_ethercat
colcon test --packages-select gripper_controllers robot_hw_ethercat
colcon test-result --verbose
```

`test/fixtures/pp_gripper.yaml` contains synthetic data and is not installed.
Tests exercise the protocol state machine, raw PDO adapter and actual ROS Action
client/server, including an Action-to-raw-PDO feedback round trip. None accesses
an EtherCAT device. Offline success is not authorization to enable or move hardware.
