# 硬件 Bring-up 顺序

必须按单电机、单模块、架起整车、落地四级推进。上一级未满足验收项时不得进入下一级。

## 共用准备

- 主电源物理断路器可触达；CAN 与逻辑电源分开检查。
- 车辆可靠架设，轮子高速旋转范围无人和线束。
- 终端电阻、总线波特率和电源极性已测量。
- `config/swerve_params.yaml` 已复制一份带日期的现场版本。
- 现场文件保持 `can.allow_fallback_limits=false`；该逃生阀仅允许 `vcan*`/`fake*` 测试。
- 已在官方工具中记录 8 台电机的 PMAX/VMAX/TMAX，并理解驱动将以读回值为准。
- 开两个终端观察 `/diagnostics` 和 `/swerve_driver/odom`。

启动命令：

```bash
source install/setup.bash
ros2 launch dm_swerve_driver swerve_driver.launch.py \
  params_file:=/absolute/path/to/site_swerve_params.yaml
```

停止命令：

```bash
ros2 service call /swerve_driver/disable std_srvs/srv/Trigger {}
```

## A. 单电机台架

1. 总线上只连接一台电机，运行 `dm_swerve_bringup_check --motor ESC:MST`；转向电机用 `--steering`。
2. 核对 PMAX/VMAX/TMAX、ERR、温度和 p_m。
3. 使用官方上位机或隔离的单电机台架程序给极低目标；生产 lifecycle 驱动要求 8 台电机全部通过启动门，不能在缺 7 台电机时激活。
4. 验证 enable、正常反馈、disable 和硬件 TIMEOUT。
5. 在电机运动中物理拔掉 CAN，测量从最后一帧到电机失能的时间，必须不超过 `timeout_register_ms`（计入测量误差）。
6. 断电复验 p_m 持久性；记录 `0x09` 写入是易失、掉电保存，还是需要额外保存命令。

验收：方向、单位、反馈 ID 正确；无意外使能；通信中断后固件按 TIMEOUT 失能。

## B. 单模块台架

1. 在隔离台架连接一台转向和一台驱动电机，确认两条 MST_ID 独立；仍使用台架工具，不绕过生产驱动的 8 电机启动门。
2. 轮子悬空，从 +x、+y、170° 目标验证 optimize 和反速。
3. 验证 20° 对齐门控：转向误差大时驱动为零，收敛后自动恢复。
4. 从 +179° 请求 -179°，确认选择约 +1° 的反速分支而不是跨过 +180°；用慢速抓取整条 setpoint 轨迹，确认始终位于扣除 margin 后的机械区间内。
5. 在机械端点附近分别注入 margin 区、物理端点容差内和容差外量测：前两者不得中断控制帧，且目标仍在 safe 区；容差外量测必须锁存并让四个驱动归零，活动越界时拒绝 clear，量测恢复后仍需人工 clear。
6. 在完整 8 电机测试架上分别阻断该模块的转向/驱动反馈，确认任一失联都会让四个驱动命令归零；恢复后按分类策略自动重使能。

验收：转向/驱动符号与 YAML 一致，有限区间分支和门控平滑，电机输出不改规划分支；边界噪声不造成停帧，真实越界走安全锁存；可恢复故障在次数上限内不需要重启节点，不可恢复故障必须人工 clear。

## C. 架起整车

1. 接入 8 电机和 IMU，先运行只读审计。
2. 先逐项制造启动失败：断开一台反馈、阻断一个限幅寄存器回复，并在 G_s>1 时制造 p_m 缺失/不一致；每项都必须拒绝 activate。恢复后启动节点，确认四转向 `seeded_from_multi_turn=true`，全部电机 ERR=1。
3. 依次发送纯 +x、纯 +y、纯自旋和对角命令，目视核对四轮方向。
4. 记录 CAN 抓包，确认每控制周期 8 帧集中发送，目标散布小于 1 ms。
5. 断开一个电机反馈：达到 `feedback_silent_cycles` 时四个驱动命令必须全零，转向保持；反馈恢复并确认 enabled 后才能恢复驱动。
6. 断开 IMU，确认仅 yaw 切换到轮式估计且 odom covariance 膨胀；恢复 IMU 时位姿不得跳变。
7. 注入欠压/通信丢失，确认恢复命令间隔不小于 1 s，三次失败后锁存；注入过流、MOS/线圈过温、编码器和过载，确认立即锁存且不自动 clear。
8. 在锁存态先执行 disable→enable，确认锁存和恢复计数不能被绕过；再调用 `clear_faults`：缺任一 enable 回复时保持锁存，8 台均确认后才解锁。另验证 rezero（仅失能时）。
9. 注入一次 CAN write/collect 异常，确认进入 transport-faulted、驱动命令为零；恢复后先完成一个完整反馈周期，再恢复运动。

验收：严格启动门、单失联停车、分类恢复、次数上限和锁存均与设计一致；恢复不造成 odom 跳变。

## D. 落地低速

1. 清空场地，速度/加速度限制降到保守值，旁站人员持物理断路器。
2. 先直行 0.5 m，再后退、横移、原地小角度旋转。
3. 执行半径已知的低速圆弧，对比 odom、IMU 和地面实测。
4. 逐步提高速度，验证去饱和、门控阈值和 cmd timeout。
5. 按 `calibration.md` 完成轮径、ks/kv/ka、转向参数拟合。

验收：实测轨迹误差满足项目指标，电流/温度处于电机规格内，所有现场参数和原始数据归档。
