# 四舵轮现场标定手册

日期：2026-09-12。适用软件：`8ebbf99`，Kinco FD CSP/CSV + IgH + BRT 多圈编码器。
参数含义与公式见 [标定说明](swerve_calibration_overview.md)，现场填写
[记录模板](swerve_calibration_record_template.md)。电机标定只采用 EtherCAT CSP/CSV 方案。
4 个外置 BRT 编码器保留 CANopen；本手册的 CAN 读回、SYNC、心跳及双源标定步骤
均用于这些编码器，不用于电机控制。

本文命令按 ROS 2 Humble、节点名 `/swerve_driver` 编写。以下命令供现场人员按步骤执行，
不是已执行记录；所有验收值由机械、电控和控制负责人填写，空项不得视为通过。

## 1. 执行顺序与准备

顺序为：设备映射/比例 → 机械几何和方向 → 双源零点 → 机械限位/背隙 →
驱动器闭环 → 负载轮径 → 主备/IMU → 转向规划 → 残差/协方差 → 整车复验。

准备角度治具、直尺/激光测距、转角或转数基准、轮胎/载荷记录、可录制 CAN/PDO
及驱动器响应的工具。全车首次使能时轮子离地且车辆可靠支撑，物理断电可立即触达。
停掉导航、遥控和其他 `/cmd_vel` 发布源，验证只有标定人员控制运动。

单模块方向/伺服整定使用厂家上位机或独立台架程序。整车 ROS 驱动的启动门要求
8 轴和 4 外置编码器齐全；不能把缺模块时的拒启动当作标定障碍而绕过。
厂家工具输出运动命令时先停 ROS 控制，避免两个程序同时控制同一驱动器。

建立带日期的现场目录，保存代码提交、配置、两类标定文件和记录表。
复制仓库的 `config/kinco_params.yaml` 为现场 YAML；其几何值也是占位值。
齿数、计数分辨率、周期和阈值均需填写证据来源，不能直接照用算例。

## 2. 先核对设备映射和比例

### 2.1 建立四模块映射表

逐个识别转向电机、驱动电机、外置编码器及序列号。填写 FL/FR/RL/RR 与
`slave_positions`、`node_ids` 对照；从站遍历顺序不等于四模块逻辑顺序。

当 ROS 未控制总线时，可用 IgH CLI 只读查看：

```bash
ethercat slaves
ethercat master
```

核对 FD vendor/product、驱动固件及物理接线。真实位置移动与软件模块名必须一一对应；
不要仅根据“有 8 个从站”判断映射正确。

### 2.2 读取外置编码器规格

下面以 node=1 为例，编码器 CAN 为 1 Mbps。先确认该口由编码器独占、没有其他 SDO 主站。
在一个终端接收，另一个终端逐条发只读请求：

```bash
# 接收终端；can0 是示例接口名
candump -L can0
```

```bash
# 请求终端；0x601=0x600+node1，依次读取 6501、6502、6004
cansend can0 601#4001650000000000
cansend can0 601#4002650000000000
cansend can0 601#4004600000000000
```

node2/3/4 的请求 ID 相应为 602/603/604，回复 ID 为 582/583/584。
核对索引、子索引及 expedited 回复长度，数据按低字节在前解码。
例如 `581#4301650000000100` 表示 node1 的 6501=65536；这只是解码示例。
6502 的 2/4 字节回复按实际声明长度解析。0x80 是 SDO abort，不能把错误码当位置。

填写每个节点的 6501、6502；“16 位编码器”不足以确定多圈范围。
核对 0x6004 总位置在硬件范围内、TPDO2 为一个 32 位 6004，且未启用会改变计数单位的缩放。
生产客户端会校验这些条件，再配置同步 TPDO2 和心跳。

### 2.3 核对三种比例

1. 从图纸/BOM 取得 Gs、Gd、齿圈 Zr 和小齿轮 Zp。
2. 在厂家允许的禁能移动或低速台架模式下，用独立角度/圈数基准验证：
   电机转数/舵轴转数=Gs，电机转数/轮子转数=Gd，外置转数/舵轴转数=Zr/Zp。
3. 读电机 6064，核对一次已知电机转动对应的计数 Rm；检查电子齿轮及用户单位。
4. 小角正反移动复测，避免只在一个点对上。无法手动转动的减速器不要强扭，
   使用厂家规定的台架方式。

填写配置后检查软件仍能表示扣除 margin 的完整舵角范围。比例不对先修正比例，
不得用安装零偏或轮径掩盖。

验收证据：8 轴/4 编码器映射表、规格读回、图纸齿数和比例复核记录。

## 3. 几何、正方向和初始范围

### 3.1 几何

测量四个转向轴中心位置。当前模型为中心对称矩形：
前后中心距写 `chassis.wheelbase_m`，左右中心距写 `chassis.track_m`。
四轮对角/两侧测量明显不一致时先检查装配，不要用一个平均数掩盖非矩形机构。
记录轮胎型号、胎压（如适用）、整车质量和四角载荷。

### 3.2 方向

从上向下观察，舵轴逆时针小角移动为正。分别核对：

- 电机侧换算后的舵角是否增加，对应 `steering.invert`。
- 外置总计数换算后的舵角是否增加，对应 `kinco.encoder.direction`。
- 轮子零舵角时正转是否推动底盘向 +x，对应 `drive.invert`。

正反方向都验证，读数变化量应与物理动作一致。齿圈/小齿轮啮合可能使计数方向反向，
应根据实际动作确定符号，不能从“啮合”二字直接套一个符号。

初步依据机械图纸设置物理范围。实际机构是 ±180°限位时保留该限制；
后面只缩小为实测共同范围或增加向内裕量。

## 4. 首次双绝对源标零

### 4.1 以 inactive 方式启动

当前常规 launch 会自动 configure/activate。标零时直接运行节点，手动管理生命周期：

```bash
# 目标机已构建 IgH 版本；使用实际安装目录和现场参数文件
source /opt/ros/humble/setup.bash
source /absolute/path/to/workspace/install/setup.bash
ros2 run dm_swerve_driver swerve_driver_node --ros-args --params-file /absolute/path/to/site_kinco.yaml
```

另一个终端：

```bash
ros2 lifecycle set /swerve_driver configure
ros2 lifecycle get /swerve_driver
```

确认结果是 inactive。若仍是 unconfigured，检查日志中未填写或非法参数，先修改现场
YAML 并重启节点。外置差异阈值、恢复步长必须 >0；先根据器件精度和初步背隙给出有
依据的保守初值，随后用实测收敛，不能填写任意大数解除检查。

`snapshot_path` 的父目录须已存在且运行用户可写。首次可没有快照文件；
标零服务会创建它，正常 activate 则要求快照存在。

### 4.2 治具对齐与服务调用

1. 四轮静止，用独立治具对齐车体 +x，确认轮面平行且正轮速方向已核实。
2. 确认控制循环已停。如之前是 active，可先调用 disable；直接 inactive 启动时无须先 activate。
3. 调用：

```bash
ros2 service call /swerve_driver/rezero_steering std_srvs/srv/Trigger '{}'
```

4. 要求 success=true，日志无节点缺失/身份错误/存储失败。
5. 保存并检查 `snapshot_path` 与 `snapshot_path.calibration`。后者记录四轮外置安装
   偏移与电机参考；重启时会覆盖 YAML 对应零偏。

在当前代码中，服务内部保持禁能并采样两路绝对值，不要求轮子先通过正常使能的
双源一致门。服务没有自动测量轮子物理朝向，也没有标零后独立治具复测；
success 只能证明本次采集/配置检查/写文件成功，不能代替下一步验收。

### 4.3 独立验证与掉电重验

```bash
ros2 lifecycle set /swerve_driver activate
ros2 lifecycle get /swerve_driver
ros2 topic echo /joint_states --once
ros2 topic echo /diagnostics --once
```

核对四轮关节角接近 0，物理轮面仍沿 +x；Kinco 编码器来源为 external absolute encoder。
用治具核对若干区间内已知角，例如 0、±30°、±60°，分别从两侧逼近。
指定单舵角使用独立台架工具；现有 ROS 接口只接底盘速度，可能主动选择反轮速分支。

正常停机、断电再上电，重新 configure/activate，验证无需重标零仍通过。
重启时不要无条件执行 rezero；先保留上次零点，才能检验绝对位置保持能力。

验收：四轮零偏、比例误差、正反重复性、两源差异和重启重复性达到记录表中预定指标。

## 5. 机械限位、margin 与背隙

只用符合厂家要求的低速台架/人工检查确认止挡位置，不用大目标和大力矩撞限位。
每轮记录实际最小/最大舵角、触及止挡前的可控区间以及测量不确定度。

当前四轮共用一组限位，可保守取：

```text
joint_limit_min_rad = max(各轮实测下限)
joint_limit_max_rad = min(各轮实测上限)
safe_min = joint_limit_min_rad + margin
safe_max = joint_limit_max_rad − margin
```

safe 区间需包含 0、跨度不少于 π，物理跨度至多 2π。真实共同范围达不到时属于当前
规划器适用条件不满足，应处理机构/规划需求，不能扩大软件限位让校验通过。

margin 根据最不利速度/负载下的过冲、背隙和角度不确定度向内保留。
tolerance 根据物理端点附近的静态读数噪声、量化和测量不确定度确定；不要用它接受
真实越过机械限位的运动。目标仍必须在 safe 区间。

对每个已知角，从顺时针和逆时针两个方向各逼近若干次，计算：

```text
方向重复性 = 同方向重复读数的离散范围
双向差 = |顺时针逼近的平均角 − 逆时针逼近的平均角|
比例误差 = 编码器换算角变化 − 独立测角变化
```

两源差异不能完整反映外置编码器自身齿轮背隙，必须保留独立测角结果。
零点对而远端误差线性增大，优先查齿比/分辨率；同一点从两侧接近结果不同，优先查背隙。

## 6. 伺服环与运动限制

先在 KincoServo 中按具体电机和驱动器手册完成电机参数、速度环、位置环及保存。
转向从小角阶跃和慢速往返开始，驱动从低速正反平台开始；每轮在空载及代表性负载下
记录目标/实际、稳态误差、响应时间、过冲、振荡、电流和温度。
合格指标事先填写，不能以提高限流或误差门限替代修正闭环。

Kinco 当前运行模式为转向 CSP=8、驱动 CSV=9。速度环和位置环在 KincoServo 中整定，
位置前馈默认由已保存的驱动器参数
决定；只有确认原始单位后才启用 `kinco.write_position_feedforward`。
加速度前馈参数不能按“越大前馈越强”推断，应遵循该固件定义。

完成低速跟踪后，再确定：

| 项目 | 观察 | 调整原则 |
|---|---|---|
| 转向斜率 | 全程最大跟踪误差、端点过冲 | `steering.max_slew_radps` 不超过可靠跟踪能力 |
| 轮速加速度 | 地面附着、驱动电流、实测速度滞后 | `chassis.max_wheel_acceleration_mps2` 按载荷整定 |
| 近零死区 | 零速噪声与需要实现的爬行速度 | 同时满足不乱转向和小速度可执行 |
| 运动上限 | 电机速度原始值与物理速度 | 换算后仍在厂家许可范围，CSP/CSV 可表示并可跟踪 |

软件运动上限不是急停性能指标；电机闭环跟踪能力和实际停车距离都要实测。

## 7. 负载下有效轮径

先锁定已独立核实的 Gd。轮面沿直线、地面无明显滑移，选择足以降低测距相对误差的
直线段，正反各测至少 3 次，使用代表性载荷。

采集外部实测距离 D 和各驱动关节角增量 Δφ。四个轮关节名为
`front_left_wheel_joint`、`front_right_wheel_joint`、`rear_left_wheel_joint`、
`rear_right_wheel_joint`，单位 rad。当前 joint_states 中这些角由电机位置和已配置
Gd 换算，不能在 Gd 未确认时把它们当独立齿比证据。

```text
r_i = |D_true| / |Δφ_i|
若直接读取电机角：r_i = |D_true| × Gd / |Δq_motor_i|
多次测量可拟合：r_i = Σ(φ_j × D_j) / Σ(φ_j²)   # D_j、φ_j 使用一致符号
```

计算前剔除真实起终点未对齐、明显打滑、舵角变化和时间窗口不一致的样本，并记录剔除
原因。不要用已经过残差剔除的底盘 odom 代替原始轮关节角做这个标定。

将四轮结果与胎压、载荷、磨损一起比较。四轮一致时取有依据的公共半径；明显不同则
先处理机构/轮胎。当前 `chassis.wheel_radius_m` 只有一个值。
改 YAML 后重启节点，以独立测试段验证，而不是用同一数据拟合后直接宣称通过。

若 Gd 正确且其他几何已核准，可用下式做小幅复核：

```text
r_new = r_old × |D_true| / |D_odom|
```

这只适用于对齐、无滑移的直线实验，不能拿来补偿偏航、齿比或 IMU 错误。

## 8. 双源阈值、掉线备份与恢复

记录外置原始角 θe 和电机换算角 θm，覆盖静止、两方向转向、加减速及代表性负载。

```text
d_i(t) = |θe_i(t) − θm_i(t)|    # 轴侧 rad，直接线性差值
```

选 `source_disagreement_threshold_rad` 时覆盖正常背隙、弹性和两总线采样时差；
时差造成的量级可估为 |舵角速度|×|采样时差|。阈值应高于健康数据的高分位/合理上界
加测量裕量，同时低于要求识别的异常幅度。两者无法区分时先改善测量和机构。
当前阈值四轮共用，不能独立给某一轮放宽。

`maximum_offline_axis_motion_rad` 要覆盖合理停放移动，仍能识别不可接受的多圈跳变。
0 值表示不容许读数变化，可能因量化差异拒启动；不要靠删除快照让检查失效。

`maximum_rejoin_correction_rad` 的单位是 rad/周期。控制频率 f 下，其名义修正速率
约为 f×该值；修改控制频率时需重新核对。它限制的是恢复偏差的消除速度，
不代替舵角目标的 `max_slew_radps`。

在离地/受控低速条件下中断一只外置编码器的报文：

1. 记录掉线前角度和来源。
2. 确认转为 motor encoder backup，诊断 WARN；EtherCAT 电机仍健康。
3. 恢复报文，确认来源归队、第一步连续、之后有界回归外置绝对角。
4. 用记录回放/仿真注入双源超阈值和多圈跳变，验证拒使能/锁存；不要为做此试验强行
   扭轮跨止挡，也不要在实车上直接篡改编码器多圈预置值。

## 9. IMU 和底盘几何复验

静止记录 yaw/角速度零偏，随后用外部角度基准做小角正反旋转，再走直线和圆弧。
检查 +z 角速度符号、yaw 方向、时间连续性和与底盘安装朝向的一致性。

当前节点直接取 IMU 四元数的 yaw 和 `angular_velocity.z`，不会自动通过 TF
变换 IMU 安装方向，也不会在此节点估计陀螺零偏。输入应由 IMU 上游完成必要的
标定/坐标转换。四元数有效、姿态估计可用，IMU 发布频率应足以满足超时设置。

核对纯转动时各轮行程与旋转角：

```text
|Δs_i| ≈ |Δψ_true| × sqrt(x_i² + y_i²)
```

一次纯旋转只约束到转动中心的半径，不能单独辨识 L 和 W；继续以实际中心距测量
为准。底盘 yaw 可以连续跨 ±π，计算多圈底盘旋转时应展开 yaw 序列，这与有限舵角
禁止跨机械边界是不同问题。

断开 IMU 数据应转轮式 yaw，恢复时检查 pose 没有突跳；记录降级期间误差，不把
“自动恢复”当作惯导标定合格。

## 10. 转向规划、滞回和对齐门控

用受控台架/仿真先验证边界；实机只执行机械测量已确认允许的轨迹。
存在 margin 时不要为了复现某个角度而把目标强行放进禁止区。

| 场景 | 应观察到的行为 |
|---|---|
| 当前 +179°，期望轮向 −179°，安全范围为 ±180° | 通常选择约 +1°的反轮速等效目标，区间内实际路程约 178°；不能当成跨 +180°的 2° |
| 当前 +179°，期望轮向 0°，margin=0 | 允许选择 +180°反轮速候选，约 1°；有 margin 时该端点可能不可用 |
| 候选代价接近且指令小抖动 | `flip_hysteresis_rad` 抑制来回换分支 |
| 任一轮目标误差超过 align_threshold | 四个驱动目标均为零；转向继续按安全路径对齐 |
| 超时且 hold_steer_on_timeout=true | 保持当前安全舵角，驱动零速 |

“期望轮向”是底盘速度解算出的运动方向，不是绕过分支器强制指定的舵关节角。
当前没有 ROS 单舵角命令服务；`/cmd_vel` 可能选择反轮速，因此不能凭发布
“向后走”就断言舵轮应转到 180°。

门控调参应同时记录舵角、轮速、车体偏航/侧滑和重新放行延迟。先排除零偏与闭环
跟踪问题，再考虑调整约 20°的默认门限，不能为了不停顿就直接关门控。

## 11. 最小二乘残差与协方差

### 11.1 残差数据如何取得

当前速度残差定义为：

```text
u_i = [v_i cosθ_i, v_i sinθ_i]
u_pred_i = [vx − ω y_i, vy + ω x_i]
r_i = norm(u_i − u_pred_i)        # m/s
```

先用有效轮组解算三维底盘速度，再检查每轮残差，必要时剔除最大超阈值轮并重算。
标定用健康原始轮数据计算“首次拟合”的残差分布，并验证完整迭代剔除行为；
不能只看剔除之后剩余轮的小残差来反推阈值。

ROS 可录制：

```bash
# 先确认实际 IMU 话题；输出目录必须尚不存在
ros2 bag record -o /absolute/path/to/new_run_01 /cmd_vel /joint_states /swerve_driver/odom /diagnostics /imu/data
```

离线按 joint name 对应各模块，取轮关节 velocity×现场 r 得到 v_i，转向 position
得到 θ_i，再按上述矩阵拟合。需剔除来源切换、时间不齐、静态采样无有效速度等段。
joint_states 按配置发布频率输出，不一定覆盖每个控制周期；严格标定控制周期阈值时
需配套 PDO/CAN/内部采集。

当前 diagnostics 发布 slip 标志和轮名，不发布 r_i 数值，且通常每秒发布一次，
可能漏掉很短的单周期 slip。也未发布每轮电机原始舵角和两源差值；这些由厂家 trace、
PDO/CAN 记录换算。不要把 diagnostics 当作完整高频测量流。

### 11.2 确定阈值

分别采集健康直线、横移、转弯、加减速及不同载荷/地面数据，列出各轮残差中位数、
高分位和最大值。用健康高分位/正常上界加合理裕量形成候选阈值，再用受控单轮异常
回放验证检出率、定位正确性与健康误报率。

默认 `odometry.slip_residual_threshold=0.25` m/s 只是初值，不是通用标准。
超阈值也可能由轮径不一致、零偏、时间错位、传动弹性或编码器故障引起，先查根因。
四轮一致共模偏差可能不触发，残差为零不证明没有打滑。

### 11.3 协方差

用独立位置/姿态/速度基准，在相同时间窗口下统计 odom 误差，系统性偏差单独记录并
优先修正。用重复实验的误差方差设置 pose/twist 的六维对角基线。

| 参数 | 对角顺序 | 单位 |
|---|---|---|
| `odometry.pose_covariance_diagonal` | x、y、z、roll、pitch、yaw | 前三项 m²，后三项 rad² |
| `odometry.twist_covariance_diagonal` | vx、vy、vz、ωx、ωy、ωz | 前三项 (m/s)²，后三项 (rad/s)² |

未观测自由度不要填成零方差。当前实现是固定基线乘状态系数，不是完整的协方差传播：

```text
scale = (IMU降级 ? imu_fallback_covariance_scale : 1)
      × (有效模块不足4 ? missing_module_covariance_scale : 1)
      × (检测到打滑 ? slip_covariance_scale : 1)
```

默认 missing=4、slip=4 时，一轮被剔除且发生 slip 的总倍率为 16；如再叠加
IMU fallback=10，则为 160。分别用降级实测误差复核各系数，并核对下游 EKF 的融合方式。
当前没有专门针对外置编码器备份模式的独立协方差系数，该模式也需单独记录误差。

## 12. 整车低速复验与停车

在全部静态标定完成后，清空受控场地并使用低速限制。下例只用于已经确认具备运动
条件的整车直行检查，0.03 m/s 与持续时间是操作示例，应按现场缩小：

```bash
timeout -s INT 3s ros2 topic pub --rate 20 /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.03, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

观察实际停止后再换工况。发布零命令和 watchdog 归零不等于实车瞬时停止。
依次验证前后直线、左右横移、小角正反旋转和低速圆弧，记录外部轨迹、odom、舵角、
驱动速度、门控、slip、两源和 WKC/AL 状态。

检查 `control.rate_hz` 与 DC 周期满足 `dc_cycle_ns=1e9/rate_hz`；
例如 100 Hz 对应 10000000 ns，只代表换算关系，不证明 FD 支持该周期。
核对实际周期抖动、loop_overruns、编码器采样耗时和驱动器周期要求。

在专门台架分别验证：停止 cmd 发布、单外置编码器掉线、单电机离线、EtherCAT 断链、
IMU 丢失和故障清除。真实拔线必须测最后有效控制数据到实际降速/驱动器安全态的时间；
不是看服务回复或软件标志。FD watchdog 和 0x605E 的实际行为按厂家固件实测。

以下是按不同状态选择的独立操作，不要把清错当成 disable 后的固定下一步。
停止当前控制：

```bash
ros2 service call /swerve_driver/disable std_srvs/srv/Trigger '{}'
```

故障原因消除、控制线程仍运行且处于锁存停车态时，请求清错：

```bash
ros2 service call /swerve_driver/clear_faults std_srvs/srv/Trigger '{}'
```

lifecycle 仍是 active、此前仅通过 disable 停止控制时重新使能：

```bash
ros2 service call /swerve_driver/enable std_srvs/srv/Trigger '{}'
```

disable 可用于停止当前控制；clear_faults 要求控制线程仍在运行，锁存停车态可以调用，
但“queued”表示请求入队，不代表已经清除。先确认故障原因消失，再看诊断与轴状态。
enable 服务仅在 lifecycle active 时有效；inactive 要用 lifecycle activate。
disable→enable 不会自动消除既有锁存或重置恢复次数。

## 13. 保存、变更与复标

1. 正常 disable，确认停机快照成功；再退出节点。
2. 归档现场 YAML、快照、`.calibration`、驱动器参数备份、bag/trace、记录表和代码提交。
3. 按修改后的 YAML 重启/configure，再用独立工况复验；不要只依赖 `ros2 param set` 回复。
4. 更换轮胎或载荷明显变化：复标有效轮径并复验加速度/残差。
5. 动过舵轮安装、编码器、齿轮、齿比/分辨率/invert：复核方向和比例，再治具标零、
   验证限位、双源与持久化。
6. 调整控制频率、固件或伺服环：复验主备恢复步长、残差、DC/watchdog、门控和停车。

确认硬件变更后，如果旧标定文件匹配校验使 configure 失败，保留旧文件并为新硬件
版本设置新的 `snapshot_path`，创建父目录后按首次标零流程处理；不要将此办法用于
绕过未解释的启动异常。仅改电机侧比例/方向也要复标，不能因为文件匹配检查放行就沿用旧零偏。

本轮所有实际数据与签字进入记录模板，现场通过后才更新
[EtherCAT 硬件验证状态](kinco_hardware_validation_status.md)。仿真通过与实车通过分别填写。

## 14. 常见问题速查

| 现象 | 优先检查 | 避免的误处理 |
|---|---|---|
| configure 失败 | 0/空参数、DC/watchdog关系、重复ID、现有标定文件匹配 | 随便填大数 |
| 标零成功但物理不正 | 治具、轮速正向与180°歧义、模块映射 | 认为服务会自动寻找机械零点 |
| 修改 YAML 零偏仍没变化 | `.calibration` 覆盖、是否重启/configure | 反复在线改参数 |
| 零位准、转大角度越来越不准 | Gs/Ge、分辨率、电子齿轮 | 用固定零偏补比例 |
| 同角度两向接近不同 | 背隙、松动、弹性、夹具 | 盲目加位置环增益 |
| 两源都显示一致但物理角错误 | 共用错误比例/零位、独立测角证据 | 只相信双源交叉校验 |
| 边界附近锁存 | 实际机械角、tolerance来源、角度是否被错误取模 | 改 continuous 关节或放大物理限位 |
| 直行里程整体偏大/偏小 | Gd/Rm确定后再查有效轮径 | 同时乱调轮径、齿比和轴距 |
| 健康地面频繁 slip | 原始轮速/舵角同步、轮径一致性、零偏、阈值 | 直接关闭残差检测 |
| 外置掉线仍能运行 | 是否已切备份、备份误差 | 把所有 WARN 都当停车故障 |
| 断电后拒启动 | 快照/标定文件、原始读数、停放运动、设备规格 | 自动删快照或无条件重新标零 |
