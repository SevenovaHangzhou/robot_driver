# 当前框架的真机键盘运动链

2026-11-07：远端 18131 已运行真机键盘入口，18121 已启用 `--jog-motion-enabled`。两者跟随当前 `bench_dual_arm_head_wrist_force` artifact、ROS Domain 77；启动后未使能、未接管、权限空闲。尚未做自动选模及末端实机运动验收。


键盘链不使用 JTC，不调用重力补偿。右臂、左臂共享机器人本体方向定义。未选中的自由度冻结；双臂互碰和各臂自碰撞检查同时覆盖。碰撞候选余量和覆盖范围见 [真机碰撞检查](REAL-COLLISION.md)。当前几何不覆盖头部、躯干、底盘、线缆或外界障碍物。

`RealRollingSource` 将 Mink 结果转成常加加速度区间，以三次 Hermite 插值核对位置、速度、加速度及整个区间的碰撞余量。松键生成连续减速尾段；急停式软件停止或断线停止后不再续流，由 Rolling 的已配置超时制动收敛。

`CurrentStream` 使用 20 ms 采样、400 ms 未来窗口和 100 ms 替换提前量；按 ACK 提交窗口。连续按键保持一个 epoch，按已有轨迹的未来锚点替换，接缝 q/v/a 连续。每次只保留有界窗口，并同时检查控制器 buffer_capacity；不会随按住时间累积到 256 点。官方 sender 负责序号、ACK、终态、超时与 QoS。

## 入口

启用运动链需要两端显式配置。18121 的 `--jog-motion-enabled` 默认为关闭；打开该选项不会使能硬件。持有权限并发起 `begin_motion` 后，主操作台自动选择 Rolling；18121 发起关节动作时自动选择 JTC。选模规则见 [统一双臂控制权](CONTROL-AUTHORITY.md)。18131 的运动入口为：

```bash
script/start_real_keyboard.sh \
  --primary http://<工控机>:18121 \
  --artifact-dir <当前运行 artifact> \
  --model-share <配套 robot_description> \
  --domain-id <与当前运行栈一致> \
  --bind <工控机监听地址> --port 18131
```

必须使用当前运行 artifact 中的 14 轴顺序、URDF、位置余量及速度/加速度限制；主操作台会核对模型和运行参数。网页获取共享权限后，开始接管前再经主操作台准入；规划等待期间松开或释放权限，不得产生迟到的轨迹任务。

现场发行目录为 `/home/ar/gripper-jog/releases/shared-authority-20261107`。`script/start_primary.sh` 启动 18121，`script/start_gateway.sh` 启动 18131；两者都不启动实时栈。18131 使用发行目录独立 `.venv`，固定 MuJoCo 3.15.0、Mink 1.3.0、qpsolvers 4.13.0、DAQP 0.10.3；18121 保持 ROS 的系统 Python。没有修改系统 Python 包。

操作顺序：在 18121 取得权限并按现场流程显式使能，释放权限；在 18131 取得权限，确认所选机械臂与速度，开启键盘接管。默认左臂、0.5 mm/s，首个有效方向输入才请求 Rolling。单纯打开页面、获取权限或开启键盘接管都不切换控制器。释放、失焦或停止后的停车与交接仍由统一主操作台确认。

## 验证

当前接口的绑定在独立 localhost ROS Domain 上验证，未连接电机。项目测试覆盖窗口 ACK、连续接缝、停止、参数约束、输入过期和接管过程中释放权限。新配置的实机反馈和原始模型 SHA-256 已匹配；左右臂各六方向以 0.5 mm/s 生成 21 点短窗口，离线 q/v/a 与碰撞复核通过，首窗口耗时约 20–23 ms。104 对碰撞检查的当前最小几何距离约 54.1 mm，候选最小距离为 30 mm。这些结果不替代真实 TCP 标定、方向核对、现场碰撞余量或有界低速运动验收。远端检查没有发送模式切换或运动指令。

已修复 Rolling 未激活时状态消息携带 `Infinity` 导致浏览器解析失败、模型停留在加载中的问题：尚无 Rolling 反馈时，`state_age_s` 返回 `null`。严格 JSON 的 WebSocket 回归覆盖首次反馈前后；本机包检查 351 项无失败、无跳过。远端整机模型、默认 0.5 mm/s、双页互斥、释放交接与空闲断线归还验证通过，没有页面脚本错误。


2026-11-07 修复连续启动即退出：`begin_motion` 重置发送器、可能切换控制器 epoch 后，客户端只以本次启动响应及其后收到的状态更新轨迹；启动前缓存的终态不参与新会话。窗口发送响应同样作为后续反馈的时间基准，保留 200 ms 状态时效和原有使能、互斥、碰撞及动态限制。故障显示包含发送器 phase、控制器 epoch 与拒绝码。解析模型回归覆盖上一轮停车、拒绝、超时及 epoch 中断四种情况；不代表真机运动已验证。
