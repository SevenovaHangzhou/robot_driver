# 整机架构底层代码要求

> 适用范围：电机驱动、总线主站、实时控制、硬件接口、安全监控、生命周期编排——即架构文档中 L0~L2 及其直接支撑代码。
> 定位：这是对"代码应该长成什么样"的**架构约束**，不是编码规范。每条要求都标注了强制机制（CI / 评审门 / 验收测试），无法强制执行的要求不收录。
> 依据：`ARCHITECTURE.md`（目标架构）与 `DRIVER_REVIEW.md`（现有代码的正反例）——本文每条要求都能在评审中找到对应的正面或反面案例。

---

## 0. 三条元原则

一切具体要求都从这三条推导，冲突时按此裁决：

**M1 失效决定论**：底层代码的质量不由"正常路径跑得多好"衡量，而由"每一种失效的后果是否事先写下来并测试过"衡量。失效行为矩阵（谁死了→什么后果→谁兜底）是与代码同等级的架构资产，矩阵没有覆盖的失效等于未定义行为。

**M2 责任只能下沉，不能上浮**：越往下的层，责任越重、代码越少、变更越慢。安全兜底在硬件和实时域，授权和编排在非实时域，业务在最上层。任何"用上层软件保证下层安全"的设计（用 Python 心跳保证停车、用行为树保证互锁）默认拒绝，除非下层已有独立兜底。

**M3 无强制不成要求**：每条要求必须绑定至少一个强制机制——CI 检查、评审清单项、自动化验收测试或故障注入项。靠自觉遵守的要求会在三个月内被进度侵蚀，与其写了不执行，不如不写。

## 1. 可靠性要求（Reliability）

### R1 实时确定性
- 控制环有明确的周期与抖动预算（如 250Hz/1kHz，最大抖动 <100µs），**以控制环自身统计验收**（周期抖动直方图、DC 同步偏差、丢帧计数），cyclictest 只作环境基线。
- 实时路径（`read()/write()/update()`）四禁：禁动态内存分配、禁阻塞 IO（含同步 SDO/service 调用）、禁可争用锁、禁同步日志。事件沿需要记录的，置标志由诊断线程输出。
- 生命周期回调不得长阻塞：`on_error`/`on_deactivate` 里的多段停机序列必须做成分周期推进的状态机或移入独立线程，禁止在控制线程里 `sleep` 数百毫秒。
- **强制**：评审清单 + 实时路径静态扫描（禁用 API 名单）+ 8h 台架验收测试。

### R2 失效行为决定论
- 每个进程、每条总线、每个节点的死亡/断链/重启后果必须在失效矩阵中有一行，且每行做成**可重复的故障注入测试**（kill -9、拔线、断电），进 CI 或例行验收。
- "fail-closed"必须落到有界时间：授权链断裂后多少毫秒内运动被抑制，是写进配置并被测试断言的数字，不是形容词。
- **强制**：失效矩阵文档 + 故障注入测试清单，新增进程/节点时 PR 必须同步更新两者（评审门）。

### R3 看门狗完备性——监护关系双向定义
- 每条"A 监护 B"的链路必须同时回答四个问题：谁喂狗、喂狗周期、超时后 B 的行为（由 B 侧配置决定，不是假设）、该行为由什么测试验证。
- **驱动器侧的主站失联保护是硬件配置需求，不是软件层可选项**：EtherCAT SM 看门狗显式配置（不用上电默认值）、CANopen 侧 consumer heartbeat/厂商 RPDO 超时对象写入并读回。"稳态静默"的协议设计（如 PP 帧去重）必须与看门狗节拍兼容（keep-alive）。
- 反面案例：评审发现两条总线的"主站死→驱动器自主抱闸"均未配置未实测，履带存在 runaway 路径（DRIVER_REVIEW P0-2）。
- **强制**：看门狗关系表进架构文档；拔线/断电实测为出厂验收硬项。

### R4 状态机完备性——"第二次"路径与"恢复"路径同权
- 生命周期状态机必须显式覆盖：第二次激活、节点重启后重连、故障复位后恢复、断点续任务。所有会话内状态（预装载值、锁存目标、epoch 标志、缓存）必须有**显式的会话复位点**，并有"第二次 activate"的专项测试。
- 恢复路径不允许出现死锁态：任何锁存状态必须存在至少一条不依赖"重启进程"的出路，或明确声明"需重新激活"并上报诊断。
- 反面案例：CSP 预装载跨会话不复位导致二次使能跳变（P0-1）；quick-stop 在驱动器未使能时触发即永久卡死（P0-5）。
- **强制**：状态机评审模板必答"每个状态的退出路径是什么、二次进入是否干净"；恢复路径单测覆盖率纳入 CI。

### R5 层边界输入零信任
- 每层对上层输入按"可能是任意值"防御：限位/限幅/NaN 清洗在**通往硬件的最后一层出口**强制执行（写 0x607A 前的 Δ 钳制与软限位夹紧），不依赖上层"应该已经检查过"。软限位同时下发到驱动器（0x607D 等）形成双层。
- 配置也是输入：轴数、接口集、比例/偏移在激活时与实际硬件交叉校验，不符即拒绝启动——校验必须是结构化比对，不是魔法字符串门。
- 反面案例：EtherCAT 13 轴全链路无软件限位，一条坏轨迹直达驱动器（P0-3）。
- **强制**：每个硬件接口的"出口钳制"作为必备代码结构进评审清单；准入校验在 strict 模式无条件启用。

### R6 资源与行为有界
- 一切队列、历史、重试、缓存有显式上限，且**到达上限的行为是定义过的**（驱逐策略/告警/拒绝），静默丢弃与静默降级视为缺陷。上限饱和后系统的长期行为（如"封签后不再接受请求直到重启"）必须与产品运行剖面兼容——7×24 机器人上"重启进程才能恢复"的设计默认拒绝。
- **强制**：评审清单项"每个容器的上限与饱和行为"；长稳测试（72h）覆盖上限路径。

## 2. 安全性要求（Safety）——与可靠性分开陈述

### S1 保命功能硬件化
软件安全层（看门狗、限速、互锁）只能让系统**更保守**，绝不承担认证职责；急停、安全区域停机走电气回路直达 STO/SS1，软件对安全链只读。软件侧应有安全链状态的**只读观测**（进 `/robot_status` 与黑匣子）——"零可见"会让安全验收只能人工判断。

### S2 授权与执行分离（permit/lease 模式）
非实时层只做授权（发放/撤销带超时的租约），实时层逐周期强制执行；授权者死亡 → 租约在有界时间内失效 → fail-closed。这是本项目已验证的正确模式（评审正面案例），列为标准模式。推论：**运动的持续前提不允许押在非实时进程的调度延迟上**——租约心跳这类"必须按时做的小事"下沉到实时域，非实时层只做电平切换。

### S3 旁路模式管控
调试/直通/unsafe 模式允许存在，但必须同时满足：(a) 与生产入口物理隔离（独立 launch/独立确认），运行时向状态系统恒定上报降级；(b) **只旁路软件运动门，不旁路总线级与驱动器级硬故障**（bus-off、EMCY、链路断裂的停机反应不可旁路）；(c) 有书面退役计划——managed 路径修不通的每个原因是待修 bug 清单，不是加固旁路的理由。旁路模式连续存在超过一个里程碑即架构告警。

### S4 储能与重力环节的时序闭环
重力轴（升降、臂）与夹持机构的停机/去使能序列必须是"确认停稳 → 确认抱闸 → 撤扭矩"的反馈闭环，固定延时开环设计默认拒绝；急停不得引入新危险（负载跌落）在风险评估中论证。
**强制（S1~S4）**：安全相关代码独立成包 + CODEOWNERS 强制评审；旁路模式清单与退役计划进例会跟踪；停机时序进故障注入验收。

## 3. 故障可诊断性要求（Diagnosability）

### D1 每个硬件节点必须能解释自己
每个驱动/传感器节点强制实现诊断上报：心跳、故障码（原始码+译文）、总线健康（丢帧/工作计数器/重连计数）、关键温度电压。新增节点无诊断实现 = CI 拒绝合入。

### D2 零静默失效
被吞掉的异常、被丢弃的帧/目标、被跳过的步骤、被合并的指令——每一处都必须留下**外部可观测**的痕迹（计数器/诊断话题/latched 状态），只写进内存变量或只打一条 debug 日志不算。特别地："新鲜度"机制要能区分"新鲜但陈旧"（帧还在到但积压延迟增大）。
反面案例：PP setpoint 丢失不可检测、coalesce 计数器无人消费、节点 boot-up 无诊断（P1-3/P2 系列）。

### D3 黑匣子可还原任一次失败
环形录制 + 事件触发落盘（覆盖事件前后），录制话题白名单包含：指令链（cmd_vel/轨迹/permit 电平）、状态链（joint_states/statusword/故障码）、诊断链。验收标准：任取一次失败任务，仅凭黑匣子能回答"哪一层、什么输入、卡在哪个状态"。

### D4 脱栈可调试
驱动层核心库与框架（ROS）解耦并附独立 CLI 工具（使能/示波/读写对象字典），售后不带整栈可单独排障。CI 强制核心库零框架依赖（package 依赖扫描）。

### D5 失效第一现场打包
进入故障/降级态的瞬间，自动采集一次结构化快照（各状态机当前态、最后 N 条指令、总线健康、租约状态）随错误码上报——让"为什么停了"的答案在第一现场，而不是靠事后复现。
**强制（D1~D5）**：诊断规范文档 + 节点模板；"黑匣子还原演练"进里程碑验收。

## 4. 复用性与可移植性要求（Reusability）

### U1 核心与传输分离
协议状态机与总线后端分离（CiA 402 核心 + EtherCAT/CANopen 两个传输后端）、驱动逻辑与框架分离（核心库无 ROS 依赖，硬件插件只是薄封装）。判据：换总线/换 ROS 版本/换驱动器型号，各自只动一层。

### U2 契约唯一源
同一事实（轴表、关节名、限位、比例/偏移、接口集）只允许一处权威定义，其余位置**生成或校验**，禁止多处手工复制。反面案例：同一套轴契约硬编码在 URDF/C++/Python/yaml/测试五处，改一个轴动五处（评审 §4.2）。
**强制**：单源生成脚本 + CI 一致性比对；零位/标定工具修改参数时必须同步重算派生量（如限位）并由测试断言。

### U3 上游依赖的诚实管理
fork 必须记录基线 commit 与补丁清单；补丁面超过可跟随上游的规模时，**正式承认硬分叉**并按自研代码承担全部维护责任（安全参数变更必须同步更新记录——文档与代码漂移即 CI 失败项）。已确认废弃的机制物理删除，不留在热路径。

### U4 配置即合同
参数带版本、带来源、带确认状态（机器可读字段，不是注释里的中文警告）；strict/生产模式的门禁只认结构化字段。机型差异用 overlay，不用复制粘贴整套配置。

## 5. 可测试性要求（Testability）

### T1 无硬件可测
每层有 fake/mock 后端（FakeBus、GenericSystem），总线级异常（丢帧、超时、EMCY、bus-off）可注入；仿真与真机共用同一套上层配置，只换硬件插件。

### T2 测行为不测实现
测试断言对外契约（接口语义、时序承诺、失效行为），不断言内部协议细节；判据：**合理的重构不应要求重写测试**。测试行数远超生产代码且深度耦合内部状态，是复杂度失控的症状而非质量的证明（评审 §2.2）。

### T3 故障注入是一等测试
每个失效矩阵条目、每条看门狗链路、每个状态机恢复路径都有对应的注入测试；"第二次 activate""上限饱和""断电重启"是必备用例族。

### T4 验收只认自动化
每个里程碑的验收标准是可重复的自动化测试与量化指标（成功率、抖动、还原能力），现场演示成功不构成验收。

## 6. 可演进性要求（Evolvability）

### E1 复杂度预算
每层复杂度与职责规模匹配。硬性触发架构评审的信号：单文件 >1500 行、单类 >30 个方法、自研了标准组件能覆盖 80% 的机制（executor/事务引擎/消息自验证）、测试代码量超过生产代码且测的是自造协议。"用 3.6 万行服务 3 个子系统"这类量级错配（评审 §4.2）应在膨胀早期被本条拦截。

### E2 偏离必留痕（ADR 纪律）
任何对基准架构的偏离（双 controller_manager、频率选择、总线划分）必须有决策记录：动机、代价、回退条件。有 ADR 的偏离是设计，没有 ADR 的偏离是债务。

### E3 接口冻结与守护
跨层接口（msg/srv/action、硬件接口集、错误码表）集中管理，CODEOWNERS 强制评审；分层依赖用显式白名单 + CI 静态检查守护，不靠自觉。分支纪律：修复只进主线，长命并行分支（尤其携带独有修复的）是集成风险，按周清理。

## 7. 落地：要求 → 强制机制对照表

| 要求族 | CI 自动检查 | 评审门（人工必查） | 验收测试 |
|---|---|---|---|
| R1 实时确定性 | 实时路径禁用 API 扫描；核心库零 ROS 依赖 | 生命周期回调无长阻塞 | 8h 控制环统计；满载抖动 |
| R2/R3 失效与看门狗 | 失效矩阵文档与测试清单同步检查 | 新进程/节点必须更新矩阵 | 故障注入全清单（kill/拔线/断电） |
| R4 状态机 | 恢复路径测试覆盖 | 状态机模板必答项 | 二次激活/重连/复位专项 |
| R5 输入防御 | strict 模式准入无条件启用 | 出口钳制代码结构 | 坏轨迹/坏配置注入 |
| S 安全 | 安全包 CODEOWNERS | 旁路模式清单与退役计划 | 停机时序/抱闸/负载跌落 |
| D 诊断 | 节点无诊断实现拒绝合入 | 静默失效逐条排查 | 黑匣子还原演练 |
| U 复用 | 契约单源比对；依赖白名单；文档-代码漂移检查 | fork 补丁记录完整性 | 换后端/换机型演练 |
| T/E | 测试与生产代码比值监控 | 复杂度触发信号；ADR 存在性 | 里程碑量化验收 |

## 8. 底层十诫（速查版）

1. **失效先于功能**：先写"它死了会怎样"，再写"它怎么工作"。
2. **实时路径四禁**：不分配、不阻塞、不抢锁、不打日志。
3. **狗要双向养**：谁喂狗、狗咬谁、咬完什么样，三问齐答并实测。
4. **第二次也要干净**：一切会话状态有显式复位点，二次激活有专项测试。
5. **出口必钳制**：通往电机的最后一行代码不相信任何上层。
6. **保命不进软件**：软件只能更保守；重力轴停机必须闭环确认抱闸。
7. **旁路不豁免硬故障**：unsafe 模式可以关软件门，不许关 bus-off 和 EMCY。
8. **静默即缺陷**：吞掉的异常、丢掉的帧、合并的指令，都要留下可观测痕迹。
9. **事实只写一遍**：契约单源，其余生成或校验；改零位必须重算限位。
10. **无强制不成要求**：写不进 CI、评审门或验收测试的要求，不要写。
