# Rolling 响应耗时与拒绝原因

2026-11-07，第 3、4 项本地实现。现场仍在测试第 1、2 项，本轮没有更新或重启远端 18121、18131、控制器，没有发送真机命令。第 5 项不在本轮范围。

## 响应耗时

18131 的 `diagnostics.latency_ms` 和页面新增的“控制响应与退出原因”显示最近最多 256 次的 P50、P95、P99、最大值和样本数。采样跨同一网关进程的多次按键保留，重启清零。

| 采样 | 起止定义 |
| --- | --- |
| 按键至发出窗口 | 网关收到方向命令 → 开始首窗发布 RPC；不含浏览器到网关的网络时间 |
| 按键至控制器确认 | 同一次方向命令 → 网关观察到首窗 ACCEPTED |
| 启动请求 | begin_motion RPC，包含主操作台准入、选模和保持命令查询 |
| 模型初始化 | 构造 Mink 配置和起始碰撞检查 |
| 窗口求解与检查 | 生成非空窗口并复核插值和碰撞的线程等待及执行 |
| 发布请求 | window RPC 往返 |
| 发布至确认 | RPC 发起 → 观察到对应 epoch、sequence 的 ACCEPTED；已经包含发布请求时间 |
| 规划周期 | 相邻循环的实际间隔，包含工作及调度等待 |

这些值是软件链路耗时，不是电机响应时间或动态跟随误差。来源时钟均为网关单调时钟；没有跨设备相减。首窗和续窗剩余提前量另记录为 initial_lead、replacement_lead，是按当前反馈时基估计的值，主操作台和控制器仍独立检查真实 ROS 时间。

保留每段精确三次插值、极值和碰撞检查；对速度导数为常数的区间省去无意义的多项式求根。21 点、7 轴运动/7 轴静止的相同曲线交错运行 80 次，本机纯插值检查的 P50 从 3.624 ms 降到 3.218 ms，P95 从 4.019 ms 降到 3.457 ms；新旧插值系数完全相同。这只是离线计算微基准，不代表现场整条控制链降幅。

## 提前量试验

启动入口 `script/start_real_keyboard.sh` 新增 `--timing-profile`：

| 档位 | 首窗提前量 | 续窗提前量 | 状态 |
| --- | ---: | ---: | --- |
| baseline（默认） | 120 ms | 100 ms | 保留当前现场时序 |
| trial（显式选择） | 100 ms | 80 ms | 已通过离线连续接缝与停车回归，未上真机 |

两个档位都使用 20 ms 间距、400 ms 未来窗口、30 Hz 循环。网关没有自动切档功能。每个相关阶段至少保留 30 个样本后，按窗口规划最大值 + max(发布最大值, ACK 最大值) + 超出 33.33 ms 的调度延迟 + artifact 的 replace_lead_ms 计算观测预算；单次长停顿同样计入。预算低于 80 ms 才提示可做下一档试验，提示本身不构成现场验收。

生成完成后接缝已不足 artifact 的 replace_lead_ms 时，客户端拒绝发布并退出接管；不续发过期窗口、不丢弃边界点，也不自动重试或恢复运动。运行参数不兼容时仍在首窗前拒绝。

## 具体拒绝原因

```mermaid
flowchart LR
  A[客户端三次插值复核] -->|本地超限| F[关节、区间、项目、数值、限值]
  B[Rolling 非实时批次准入] --> C[控制器私有 rejection 诊断话题]
  C --> D[18121 匹配 epoch / sequence / result]
  D --> E[18131 保留退出原因]
  E --> F
```

控制器 `/<发现的控制器>/rejection` 使用现有标准 `diagnostic_msgs/DiagnosticArray`，QoS 为 reliable、transient-local、depth 1。失败时才从非实时批次回调发布。位置、正反向速度、正反向加速度、同步制动空间的准入失败附带关节、批内段号、会话相对时间区间、实际极值和配置限值。其他失败保留 epoch、sequence、公共拒绝码，不猜测轴级原因。没有改公共 Rolling IDL、运动阈值或 RT update 路径。

诊断发布在首批 RT 交接门闩释放后进行；额外字符串、DDS 和分配只在非实时路径。可选的 `RollingBuffer.prepare(..., rejection)` 证据输出与原准入判断分开，拒绝结果和已接受缓冲区均不变。

18121 只向页面附带最近 2 s 内、与公共状态 epoch/sequence/result 和当前轴序完全匹配的诊断。ACK 与诊断到达顺序可以不同；18131 可补充已停止轮次的诊断，新的接管和运动不会继承旧错误。尚无匹配的控制器证据时，页面明确显示“尚无匹配批次的轴级诊断”，不会把客户端推断当成控制器实测原因。

客户端插值失败也给出同样的区间和量纲，并标记 `source=client_cubic`；控制器证据标记 `controller_admission`。输入超时、状态过期、Mink 无可行解、发布失败保留各自的错误码、阶段和原始退出原因。

## 验证和上线边界

本地验证覆盖统计容量及分位数、峰值阻止缩短建议、精确区间内极值、非有限数据拒绝、延迟诊断匹配、慢求解不发布、双臂连续接缝及停车、真正的控制器 ROS 诊断发布和生命周期。浏览器检查覆盖桌面、390 px 窄屏、错误文本安全显示及非真机页面隐藏。

控制器、主操作台和网关需配套更新后才能获得完整的控制器轴级证据；旧控制器配新网关仍能提供客户端检查和耗时统计。现场测试结束后再安排部署，先用 baseline 采样，确认预算后显式试用 trial。未进行真机动态跟随误差验证，未提交或推送上库。

本轮验证结果：操作台常规 Python 367 项通过，补建官方 RollingSender 绑定后另 1 项本机 ROS 传输测试通过；键盘、双端口网关、碰撞及连续轨迹 152 项通过；控制器 8 个 C++ 测试套件、60 项通过；前端输入与登录 17 项通过。受影响控制器和操作台包均构建成功，架构检查和集成补丁校验通过。并行新增的末端旋转控制已保留并完成合并后的回归。
